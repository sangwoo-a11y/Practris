# 현재 보드 추천 계산

## 퍼펙트 클리어 후보의 출처

후보는 외부 DB나 오프너 예시에서 가져오지 않습니다. `placements.js`의 `enumeratePlacements`가 현재 보드와 현재 미노 위치에서 좌우 이동·아래 이동·SRS 90°/앱의 180° 회전을 BFS로 탐색합니다. 충돌하지 않고 접지한 위치를 찾으며, 같은 네 칸을 점유하는 착지는 하나로 셉니다. 홀드 교환으로 나오는 미노는 별도로 탐색합니다.

각 후보를 실제로 고정하고 줄을 지운 다음, 바로 다음 미노가 도달할 착지도 계산합니다. 이 두 번째 미노의 개수는 추가 홀드 없는 착지 수입니다. 화면의 후보 수는 PC 완성 해법의 총수가 아닙니다. `lesson-data.js`의 예시는 시작 큐와 선택적인 풀이 예시에만 쓰이며, 실시간 후보의 답안 목록으로 쓰이지 않습니다.

## 첫 미노와 선택 방식

퍼펙트와 6–3은 시작 보드가 준비되면 첫 미노를 고정하기 전부터 자동 분석하며, 후보 창도 즉시 열 수 있습니다. 자동 분석을 꺼둔 사용자 선택은 유지합니다.

PCO·MKO를 선택하고 해당 형태를 유지 중이면 현재 단계의 목표 중 실제 이동으로 도달 가능한 배치를 추천 순위의 앞에 둡니다. 그 안에서는 확인된 PC 경로·짧은 경로·현재 계획 순서·평가 점수를 비교합니다. 이는 선택 방식의 **다음 배치**에 대한 제약이며 이후의 모든 미노가 같은 고정 도식을 따르는 증명은 아닙니다. PC 경로가 확인되지 않으면 이를 표시합니다. 형태 이탈 또는 해당 형태에 맞는 착지가 없으면 공통 PC 탐색 결과로 전환하며 이유를 표시합니다.

## 공통 퍼펙트 추천 순위

1. 실제 빈 보드가 되는 PC 완성 경로가 확인된 후보를 우선합니다. 확인된 경로들 사이에서는 수가 적은 경로, 그다음 평가 점수 순입니다.
2. 보이는 NEXT 최대 5개와 홀드로 DFS를 수행합니다. 칸 수와 지형 높이로 불가능한 가지를 줄이고, 같은 보드 점유·현재 미노·남은 큐·홀드는 메모이제이션으로 중복 탐색을 줄입니다.
3. 짧은 마무리는 SRS 착지 전체, 긴 경로는 회전·횡이동 후 하드 드롭하는 착지를 사용합니다. 기본 한도는 2,500노드와 400ms이며, 이 시간은 후보 BFS가 끝난 뒤의 PC 탐색 한도입니다.
4. 확인하지 못한 후보는 `-10000×내부 빈칸 -200×최대 높이 -8×높이 합 -3×표면 굴곡 +30×클리어 줄 +min(다음 착지 수,50)`로 평가합니다.

시간·노드·동작 종류의 제한이 있으므로 모든 PC를 찾거나 전역 최적해를 보장하지 않습니다. PC 경로 미확인은 불가능 판정이 아닙니다. 정렬은 확인된 경로와 정해진 평가 기준에서의 추천입니다.

## 6–3 추천

빈 보드에서 무작위 7-bag으로 시작하고 자유롭게 배치합니다. 현재 미노·홀드의 도달 가능한 착지를 같은 BFS로 구합니다. 각 후보의 다음 미노까지 두 수를 비교합니다.

평가 기준은 7열 점유(우물 막힘), 내부 빈칸, 최대 높이, 전체 높이, 좌우 평균 높이 차, 각 영역 안의 표면 굴곡입니다. 우물 막힘과 내부 빈칸에 큰 벌점을 주고 4줄 클리어에 보너스를 줍니다. 첫 수의 점수 35%, 그 후보 뒤 최선의 다음 수 점수 65%를 합칩니다. 다음 수가 없으면 첫 수만 평가합니다. 첫 수의 4줄 클리어는 추가 보너스를 줍니다. 홀드는 첫 수 대안에 포함하며 두 번째 수는 추가 홀드 없이 평가합니다.

추가로 각 후보 뒤 오른쪽 3열을 다음 4줄 높이까지 채울 최대 3미노의 조합을 탐색합니다. 현재 미노를 썼는지, 빈 홀드에서 다음 미노를 꺼냈는지, 기존 홀드를 교환했는지에 따라 남은 NEXT와 홀드 개수를 정확히 계산합니다. 현재 지형에서 회전·수직 드롭으로 공간을 채울 수 있고 보이는 미노의 개수가 충분한 조합에는 보너스를 주며, 필요한 미노가 아직 없거나 현재 표면에서 조합이 맞지 않으면 벌점을 줍니다. 같은 3열 상태와 남은 미노 집합은 캐시합니다.

3열 조합 검사는 해당 영역의 타일링입니다. 사이의 미노를 왼쪽에 모두 놓는 것까지 보장하는 전체 보드 해법이 아니므로 UI에도 '조합 후보'로 표시합니다. 대표 조합 J→O→L, J→S→L, J→Z→L은 실제 전체 보드의 SRS 경로를 검증한 직접 쌓기 과제로 별도 제공됩니다.

추천은 고정 과제의 목표를 따라가지 않고, 사용자가 놓은 실제 보드에서 매번 다시 계산됩니다. 4줄 클리어 뒤에도 보드와 큐를 유지해 계속 연습합니다. 이 역시 무한한 미래의 최적해는 아닙니다.

모든 분석은 Web Worker에서 실행합니다. 배치·홀드·되돌리기·모드 변경 때 이전 작업을 취소해 다른 보드의 결과가 덮어쓰지 않도록 합니다.
